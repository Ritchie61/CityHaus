# Repository assessment

Assessed branch `phase1/supabase-db-foundation` at `3b53eaa` (one commit ahead of `main` at `7ed6dc0`; the only difference is the Phase 1 handover document).

## Existing architecture

- Expo ~54.0.33, React Native 0.81.5, React 19.1.0, plain JavaScript, no TypeScript.
- Entry: `index.js` registers `App.js`. `App.js` (422 lines) is a single component using `useState` for screen switching, hard-coded `sampleListings` and a listing form that only `console.log`s. No network or backend calls.
- Two static web prototypes: `index.html` and `public/index.html` (both titled "CityHaus - Find Your Stay in PNG"). A search found no Supabase references.
- No `supabase/` directory, no CI workflows, no tests, no `.env.example`.
- `.gitignore` has no Supabase local-state entries (added via `supabase/.gitignore` in Claude's package).

## Findings relevant to Phase 1 (no action taken on the app)

1. `App.js` imports `expo-image-picker`, which is **not** in `package.json` or `package-lock.json`. `@expo/vector-icons` is imported but is not a direct dependency (it appears in the lockfile only transitively). Likely pre-existing bundling failure; out of scope.
2. `README.md` and `Folder-tree` describe an `app/` tree (navigation, screens, constants) and React Navigation which do not exist in the repo.
3. Prototype prices are free text in USD style (`$300 / month`); the Phase 1 rule is PGK.
4. Prototype listings expose `whatsapp` and `facebook` links per host. Which provider contact fields are public is an owner decision (D-PUBLIC-01).
5. Terminology differs: README says guests/hosts and "Call or WhatsApp host directly"; the handover says providers and reservation enquiries (D-PROD-01). Property types differ: README lists Home/Lodge/Apartment/Other, the prototype uses Apartment/Room.
6. README says phone-OTP login is planned. SMS delivery normally needs a third-party SMS provider, which may conflict with "no paid services" (D-AUTH-01). `supabase/config.toml` leaves `[auth.sms]` disabled.

## Compatibility requirements for adding Supabase infrastructure

- A Supabase CLI project at the repo root (`supabase/`) does not collide with any Expo file or folder.
- `supabase/config.toml` was generated by Supabase CLI 3.0.0 `supabase init`; only `project_id` was changed to `cityhaus`. Other values are CLI defaults and **must be reviewed by the owner** (D-CONFIG-01), notably `major_version = 17`, `[auth] enable_signup = true`, email confirmations off, and the commented `auto_expose_new_tables` option (relevant to least-privilege grants).
- App code is untouched: no `@supabase/supabase-js`, no env variables, no client keys (explicit Phase 1 boundary).
